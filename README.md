# کنترل از راه دور — بدون نصب برنامه روی دستگاه هدف

**جستجوی خودکار:** در پنل «افزودن دستگاه» و سپس «جستجوی خودکار در شبکه» را بزنید. تنها سرویس‌های قابل مشاهده روی شبکه محلی پیدا می‌شوند؛ کشف شدن به معنی اجازه اتصال نیست. کنترل همچنان به حساب مجاز یا تأیید جفت‌سازی نیاز دارد. ممکن است فایروال، شبکه مهمان، یا خاموش بودن سرویس مانع کشف شود.

**محدودیت مهم:** کنترل گرافیکی تعاملی ویندوز و گرفتن تصویر دسکتاپ از نشست WinRM/SSH تضمین نشده است؛ این پروژه جایگزین کامل Remote Desktop نیست. اندروید و ویندوز واقعی در این محیط آزمایش نشده‌اند. قابلیت آپلود فایل اگر توسط کاربر انتخاب شود فایل را روی دستگاه مقصد ذخیره می‌کند.

**امنیت:** پنل بدون ورود است و به صورت پیش‌فرض فقط به localhost متصل می‌شود؛ آن را در شبکه یا اینترنت منتشر نکنید. صرف رمزکردن اطلاعات در کنار کلید محلی از دسترسی سایر کاربران همان رایانه جلوگیری نمی‌کند.

یک پنل محلی با **پایتون (Flask)** که روی `localhost` اجرا می‌شود و دستگاه‌های دیگر را از طریق **سرویس‌های داخلی خودشان** کنترل می‌کند:

- **ویندوز:** WinRM (PowerShell Remoting) یا OpenSSH Server
- **اندروید:** ADB بی‌سیم (Wireless debugging)

> برنامه agent لازم نیست؛ اما فعال‌سازی سرویس مقصد ممکن است نیازمند تنظیم یا نصب مؤلفه اختیاری OpenSSH باشد.

> ⚠️ این ابزار دسترسی کامل به خط فرمان و فایل‌های دستگاه هدف می‌دهد. فقط روی دستگاه‌های خودتان و در شبکه‌ای که به آن اعتماد دارید استفاده کنید. پنل را روی اینترنت عمومی باز نکنید.

## چرا بدون agent؟

نسخه‌های قبلی یک برنامه‌ی agent روی دستگاه هدف اجرا می‌کردند. این نسخه کاملاً بازطراحی شده است:

```
 شما (مرورگر)                کامپیوتر کنترل‌کننده                 دستگاه هدف
┌──────────────┐        ┌──────────────────────────┐        ┌─────────────────────┐
│  پنل تحت وب  │ <───── │  Flask + Connectors      │ ─────► │ WinRM / OpenSSH /   │
│  localhost   │        │  WinRM · SSH · ADB        │  شبکه  │ ADB (سرویس داخلی)   │
└──────────────┘        └──────────────────────────┘        └─────────────────────┘
```

- کنترل‌کننده **به دستگاه هدف وصل می‌شود**؛ برعکس.
- روی دستگاه هدف هیچ فایلی کپی نمی‌شود و هیچ سرویس اضافه‌ای نصب نمی‌شود.
- ارتباط از طریق سرویس‌های استاندارد و رمزنگاری‌شده (SSH/HTTPS) یا سرویس داخلی ویندوز (WinRM) انجام می‌شود.

## پیش‌نیازها (فقط روی کامپیوتر کنترل‌کننده)

- **پایتون ۳.۹+** — اگر نصب نیست از [python.org](https://www.python.org/downloads/) نصب کنید و در مرحلهی نصب تیک **Add python.exe to PATH** را بزنید.
- کتابخانه‌های پایتون:

```bat
python -m pip install -r requirements.txt
```

> اگر `pip` را نمیشناسد، نگران نباشید؛ `python -m pip` نیازی به PATH بودن `pip` ندارد. اگر `python` هم شناسایی نشد، پایتون را با تیک Add to PATH نصب کنید و ترمینال را دوباره باز کنید.

- برای **اندروید:** ابزار `adb` از [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools) را دانلود کنید، پوشه را در `PATH` قرار دهید. (روی دستگاه هدف لازم نیست.)

## اجرا

```bat
cd remote-control
python -m pip install -r requirements.txt
python run_server.py
```

پنل را باز کنید: `http://127.0.0.1:8000`

روی ویندوز ساده‌ترین راه: **`start_server.bat`** را اجرا کنید. این فایل خودش پایتون را پیدا می‌کند، وابستگی‌ها را با `python -m pip` نصب می‌کند و سرور را اجرا می‌کند.

> برای اجرای فقط محلی: `python run_server.py --host 127.0.0.1`

## افزودن دستگاه

در پنل روی **«افزودن دستگاه»** بزنید، نوع دسترسی را انتخاب کنید و مشخصات را وارد کنید. دکمه‌ی **«تست اتصال»** قبل از ذخیره، اتصال را بررسی می‌کند.

### ۱) ویندوز با WinRM (پیشنهادشده)

**یک‌بار روی دستگاه هدف**، در یک PowerShell با دسترسی مدیر:

```powershell
Enable-PSRemoting -Force -SkipNetworkProfileCheck
Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private
```

- با یک **حساب مدیر** وارد شوید؛ رمز همان حساب را در فرم بزنید.
- پورت پیش‌فرض `5985` است. برای HTTPS از `5986` استفاده کنید (گواهی لازم است).
- برای انتقال فایل، **File and Printer Sharing** را فعال کنید تا از SMB استفاده شود.
- اگر شبکه‌ی شما «Public» است، دستور دوم آن را «Private» می‌کند.

در فرم پنل:

| فیلد | مقدار |
|---|---|
| نوع | ویندوز (WinRM) |
| آدرس | IP یا نام دستگاه، مثلاً `192.168.1.50` |
| پورت | `5985` (یا `5986` برای HTTPS) |
| نام کاربری | حساب مدیر، مثلاً `Administrator` |
| رمز عبور | رمز همان حساب |
| دامنه | اختیاری؛ برای WORKGROUP خالی بگذارید |

### ۲) ویندوز با OpenSSH (جایگزین)

**یک‌بار روی دستگاه هدف**، در PowerShell مدیر:

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
```

برای پوسته‌ی پیش‌فرض PowerShell (اختیاری):

```powershell
New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell -Value "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" -PropertyType String -Force
```

در فرم پنل، نوع **SSH** را انتخاب کنید، سیستم‌عامل را **ویندوز** بگذارید و پورت `22` را بزنید. رمز عبور یا فایل کلید SSH را وارد کنید.

> روی لینوکس معمولاً `openssh-server` از قبل نصب است؛ اگر نه، `sudo apt install openssh-server`.

### ۳) اندروید با ADB بی‌سیم

**روی گوشی:**

1. Settings → About phone → **Build number** را ۷ بار بزنید.
2. Developer options → **Wireless debugging** را فعال کنید.
3. **Pair device with pairing code** را بزنید؛ آدرس و کد ۶ رقمی را بردارید.
4. در پنل، نوع **اندروید (ADB)** را انتخاب کنید، آدرس جفت‌سازی و کد را بزنید و **«جفت‌سازی با کد»** را بزنید.
5. سپس آدرس **اتصال** (IP:port که در صفحه‌ی Wireless debugging دیده می‌شود، معمولاً پورت متفاوت) را در فیلد «آدرس اتصال» بزنید و **«تست اتصال»** را بزنید.
6. دستگاه را ذخیره کنید.

دستورهای معادل در ترمینال کامپیوتر:

```bash
adb pair 192.168.1.50:37123
adb connect 192.168.1.50:40123
```

> برای اسکرین‌شات، لمس و تایپ، همین سرویس داخلی کافی است. برای خواندن/نوشتن کلیپ‌بورد، اندروید بدون اپلیکیشن کمکی اجازه نمی‌دهد.

## استفاده از پنل

- **دستگاه‌ها:** لیست دستگاه‌های ذخیره‌شده، وضعیت آخرین تست و نوع اتصال.
- **ترمینال:** دستور را بنویسید و Enter بزنید. چیپ‌های آماده برای هر سیستم‌عامل.
- **فایل‌ها:** مسیر پوشه را وارد کنید، «فهرست» را بزنید، پوشه‌ها را باز کنید و فایل‌ها را دانلود/آپلود کنید.
- **صفحه نمایش:** دکمه‌ی «گرفتن تصویر از صفحه»؛ تصاویر قبلی در گالری می‌مانند.
- **کلیپ‌بورد:** خواندن/نوشتن متن (روی اندروید پیام پشتیبانی‌نشده نمایش داده می‌شود).
- **اندروید:** لمس، Swipe، تایپ، لیست اپ‌ها و باز کردن اپ (فقط برای دستگاه‌های ADB).
- **قدرت:** قفل/خواب/ریست/خاموش کردن با پنجره‌ی تأیید.
- **گزارش‌ها:** همه‌ی دستورها و رویدادهای سرور.

### نکته‌های مهم

- کامپیوتر کنترل‌کننده باید بتواند دستگاه هدف را در شبکه ببیند (همان وای‌فای یا VPN).
- اگر از `127.0.0.1` استفاده کنید، فقط از همان کامپیوتر می‌توانید پنل را باز کنید؛ از باز کردن پنل روی شبکه خودداری کنید چون احراز هویت ندارد.
- روی ویندوز، WinRM و OpenSSH هر دو سرویس داخلی هستند؛ نیازی به نصب برنامه نیست.
- برای انتقال فایل با WinRM، SMB باید فعال باشد؛ در غیر این صورت فقط فایل‌های کوچک (کمتر از ۱۶ کیلوبایت) از طریق WinRM منتقل می‌شوند.

## امنیت

- رمزها با کلید محلی `data/secret.key` رمز می‌شوند. به پوشه‌ی `data/` دسترسی ندهید؛ هر کسی به آن دسترسی داشته باشد می‌تواند رمزها را رمزگشایی کند.
- پنل هیچ احراز هویت داخلی ندارد. برای استفاده‌ی فقط محلی: `python run_server.py --host 127.0.0.1`. اگر آن را روی شبکه باز می‌کنید، جلوی آن یک Reverse Proxy با احراز هویت بگذارید.
- امنیت WinRM روی HTTP به روش احراز هویت بستگی دارد و HTTP بدون TLS از هویت سرور به اندازه HTTPS محافظت نمی‌کند؛ در شبکه‌ی عمومی از HTTPS یا SSH استفاده کنید.
- از یک حساب مدیر اختصاصی استفاده کنید، نه حساب اصلی خودتان.
- دستورهای مخرب مثل `format`، `rm -rf /`، `mkfs` و `dd` را با دقت اجرا کنید؛ این نسخه برخلاف نسخه‌ی agent، فیلتر دستور ندارد (چون دستور مستقیماً در shell هدف اجرا می‌شود). تأیید عملیات قدرت وجود دارد.
- تاریخچه‌ی دستورها در `data/rc.db` ذخیره می‌شود.

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| `'pip' is not recognized` | به جای `pip` از `python -m pip install ...` استفاده کنید. اگر `python` هم شناسایی نشد، پایتون را با تیک **Add python.exe to PATH** نصب کنید و ترمینال را دوباره باز کنید. یا `start_server.bat` را اجرا کنید. |
| `python` فروشگاه مایکروسافت را باز می‌کند | Settings → Apps → Advanced app settings → App execution aliases → `python.exe` و `python3.exe` را خاموش کنید. |
| `WinRM connection failed` | `Enable-PSRemoting -Force` را اجرا کنید؛ پورت 5985/5986 و فایروال را چک کنید. |
| `Access is denied` (WinRM) | با حساب مدیر وارد شوید یا حساب را به گروه `Remote Management Users` اضافه کنید. |
| `SMB` غیرفعال است | File and Printer Sharing را فعال کنید؛ برای درایو `C:`، share `C$` با حساب مدیر لازم است. |
| `SSH connection refused` | OpenSSH Server را فعال و سرویس `sshd` را اجرا کنید؛ پورت 22 را چک کنید. |
| `SSH authentication failed` | نام کاربری/رمز/فایل کلید را چک کنید؛ مسیر کلید روی کامپیوتر کنترل‌کننده است. |
| `adb پیدا نشد` | Platform Tools را دانلود کنید و `adb` را در `PATH` قرار دهید. |
| `دستگاه اجازه‌ی اتصال نداد` (ADB) | روی گوشی پیام اجازه را تأیید کنید. |
| `دستگاه در دسترس نیست` (ADB) | Wireless debugging را دوباره فعال و `adb connect` را اجرا کنید؛ پورت بعد از ریست ممکن است عوض شود. |
| اسکرین‌شات خطا می‌دهد | نشست گرافیکی فعال لازم است؛ روی ویندوز با کاربر لاگین‌شده اجرا کنید، روی لینوکس `scrot`/imagemagick نصب کنید. |
| کلیپ‌بورد خطا می‌دهد | روی لینوکس `xclip` یا `xsel` نصب کنید؛ اندروید پشتیبانی نمی‌شود. |
| انتقال فایل خطا می‌دهد | مسیر و دسترسی‌ها را چک کنید؛ برای WinRM از SMB استفاده کنید. |
| پورت 8000 اشغال است | `python run_server.py --port 8080` |

## محدودیت‌ها

- این نسخه به سرویس داخلی دستگاه هدف (WinRM/OpenSSH/ADB) نیاز دارد؛ روی دستگاه هدف چیزی نصب نمی‌شود، اما سرویس باید فعال باشد.
- WinRM و OpenSSH روی ویندوز نیاز به فعال‌سازی یک‌بار و دسترسی مدیر دارند.
- اندروید به Developer options و Wireless debugging نیاز دارد؛ کلیپ‌بورد بدون اپلیکیشن کمکی ممکن نیست.
- انتقال فایل با WinRM به SMB نیاز دارد؛ در غیر این صورت محدود به فایل‌های کوچک است.
- پنل احراز هویت داخلی ندارد؛ برای شبکه از Reverse Proxy استفاده کنید.
- اسکرین‌شات به نشست گرافیکی فعال نیاز دارد.

## دمو
